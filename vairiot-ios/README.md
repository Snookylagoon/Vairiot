The app scans barcodes with the camera, creates and edits assets, runs audits and blind audits, takes photos and GPS positions, and prints labels over Bluetooth. Offline work is queued in SwiftData and drained on reconnect, in the foreground and by a background task (`com.vairiot.mobile.sync`).

## Set up

- Xcode with an iOS 17+ simulator, and XcodeGen (`brew install xcodegen`).
- After changing `project.yml`, regenerate the project: `xcodegen generate` (from `vairiot-ios/`). Edit `project.yml`, not the `.xcodeproj`.
- Signing is automatic with team `J7GGB8W37T`.

## Build and run

Open `VairiotMobile.xcodeproj` and run the `VairiotMobile` scheme, or from `vairiot-ios/`:

```bash
xcodebuild -project VairiotMobile.xcodeproj -scheme VairiotMobile \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
```

The app talks to production (`vai.vairiot.com`). There is no staging build; the address is compiled into `API/APIClient.swift` (SAAS-7).

## Test

```bash
xcodebuild -project VairiotMobile.xcodeproj -scheme VairiotMobile \
  -destination 'platform=iOS Simulator,name=iPhone 17' test
```

Suites cover the sync queues, failure classification, delta sync, the audit scan recorder and asset positions (41 tests at S0 close). There is **no iOS job in CI** yet (W3). Background sync must also be checked on a real device before release.

## Release

Ad Hoc builds are distributed over the air from the platform:

```bash
./scripts/build-adhoc.sh <versionName> <buildNumber>                       # build only
./scripts/build-adhoc.sh <versionName> <buildNumber> --publish "<notes>"   # build and publish
```

Add newly enrolled device UDIDs in the Apple developer portal **before** building, so the profile includes them. `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` live in `project.yml`; from decision D3 the version moves in lockstep with the rest of the product, and build numbers never go down.

## Known limits

- No certificate pinning (SEC-L4).
